Principles

The website is a numbered set of engineering drawings. Every visual rule below exists either because engineers already read it that way, or because it keeps the page fast on a weak connection.

Drawing, not decorationGraphics follow drafting conventions (line types, sections, dimensions, balloons, title blocks) and are generated from product data wherever possible.
Paper for reading, navy for momentsData and reading happen on paper sheets. Deep navy fields mark the moments of the story: find (hero), understand (Anatomy), talk (contact) and the footer that closes it.
Every colour has one jobBrand navy is ink and action on paper; icy blue is interaction and focus; pale ice is the action on navy; steel is only for rendering metal; brass is the one warm accent and marks "the part in focus"; amber is only for pending data.
Metal only where it is the productRestrained metallic gradients appear only on bearing renderings (hero, assembled state, closing mark). UI chrome has no glass, glow, blur or shadow.
Codes are sacredPart codes, dimensions, units, drawing references and phone numbers use Latin digits, isolated left-to-right, in both languages. Persian prose and ordinary counts use Persian digits.
Honest data, weight as inputVerified and pending are always visible. Every visual decision has a byte and CPU cost, listed in the performance ledger at the end of this page.

Surface hierarchy

--paperThe page. Sections sit directly on it, separated by rules, not by boxes.
--paper-2Recessed: hover rows, the drawing frame inside the band.
--sheetRaised: inputs, the product workspace, title blocks, drawing frames. Always with a border; never with a shadow.
.navyA whole section re-tokened to deep navy: paper becomes navy, ink becomes near-white, the action becomes pale ice with navy text, the accent becomes light brass. Components inside need no special cases.
metalSteel gradients (--steel-*) and a brass cage are allowed only inside bearing renderings. Never on buttons, cards or backgrounds.

Rules

Line heightPersian body 1.85, headings 1.45 (tall ascenders and descenders). English body 1.6, headings 1.15.
No letter-spacing on PersianTracking breaks cursive joins. Uppercase and tracking are for Latin labels and mono captions only.
DigitsLatin in both languages for codes, dimensions, units, drawing references and phone numbers (6205-2RS · 25 mm · PC-04-A · 0912 719 5313). Persian prose and ordinary counts use Persian digits (۱۳ محصول).
DatesPersian pages show the Solar Hijri calendar (۱۲ مهر ۱۴۰۵) via Intl in the browser or PHP intl at publish; English pages show 4 Oct 2026.
Fallbacks and preloadSegoe UI, Tahoma and system fonts behind Vazirmatn; font-display: swap. The Bold weight is preloaded because the hero headline is the LCP element.
Minimum sizeNo UI label below 13 px (--fs--2). Running text stays within 50–70 characters; headings use text-wrap: balance.

Lines, shape and elevation

Radius 2 pxDrawing sheets have square corners. The only round things are bearings, balloons and status dots.
1.5 px structuralSection rules, sheet heads, inputs, the workspace frame, the action dock.
1 px dividersRows, cells, title-block partitions.
Dashed means "not final"Pending data, empty states, example chips. Never used for decoration.
No shadows, blur or glowElevation comes from surface colour plus a border; gradients exist only as metal inside bearing renderings. This also keeps painting cheap on low-end phones.
Focus2 px signal-blue outline, 2 px offset, on every interactive element.

Generated product drawings

Each product's section drawing is built from its boundary dimensions (d, D, B/T/C/H) with the family's template, so a drawing exists even before any photo. Open any product in the prototypes to see one. In production the Publish Engine renders the SVG into the product's HTML.

Mechanics

Logical properties onlymargin-inline, inset-inline-start, border-inline-end, text-align: start; no left/right in the stylesheet except inside drawings.
Isolate, don't flip blocksCodes sit in <bdi dir="ltr"> inside an RTL block, so they keep their order but align to the start of the Persian line.
InputsSearch uses dir="auto": a typed code runs LTR, typed Persian runs RTL; the Persian placeholder is forced RTL and isolates its example code.
Search normalisationPersian and Arabic digits, Arabic ي/ك, spaces, hyphens, slashes and × are normalised, so typing ۶۲۰۵ (Persian digits) finds 6205.
KeyboardArrow keys in the workspace tabs follow reading direction (Left = next in Persian).
Second script on each pageEnglish pages load a Persian-only subset (11.6 KB) so the brand name and family names in Persian shape correctly.

Explorer and workspace

A catalogue, not product cardsA real table: drawing glyph, designation, family, d / D / B (or the family's own symbols), provenance. Every row is a crawlable link; JavaScript only hides rows.
Family rail with countsShort family names, glyph and count; empty families are disabled rather than hidden, so the range stays visible.
Exact match lands on the answerSubmitting an exact code (or a search with one result) scrolls to the results and opens the workspace with its actions in view.
No match keeps the queryThe typed code is carried into "Ask about this code" (WhatsApp) and the inquiry form; a partial match shows a softer version of the same offer.
Workspace, desktopDocked at the inline end, sticky, no inner page-in-page: designation, d/D/B readout, tabs (Overview · Specifications · Documents), drawing before imagery, and a footer with WhatsApp / Call / Inquiry.
Workspace, mobileA bottom sheet sized to its content (max 88% height): the page behind is inert; Esc, scrim, drag-down and close all dismiss; focus returns to the row. The dock hides while it is open.
